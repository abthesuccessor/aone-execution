# 14. Canonical Data Model

## 14.1 Authority and storage policy

PostgreSQL is the canonical system of record for:

- tenant/namespace identity and version metadata;
- schemas, packages, plugins, graphs, revisions, dependencies, and deployments;
- execution, activation, dependency, token, attempt, lease, timer, signal, effect, budget, and dead-letter state;
- shared-state versions and deltas;
- checkpoint, artifact, history-event, log-manifest, usage, and audit metadata;
- idempotency decisions and transactional outbox entries.

Large immutable bodies—Graph IR, source bundles, node input/output, model/tool payloads, state snapshots, checkpoint manifests, and log chunks—are stored as encrypted content-addressed objects. PostgreSQL owns their artifact manifests, hashes, references, retention, and lifecycle. An object without a committed artifact row is garbage; an artifact row whose object cannot be verified is an integrity failure.

JetStream is a durable notification/dispatch transport, not ledger truth. Redis/Valkey is a non-authoritative cache. ClickHouse, OpenSearch, pgvector indexes, and graph/lineage projections are versioned and rebuildable from PostgreSQL plus canonical object artifacts. They never authorize, choose the current revision, or resolve runtime state.

## 14.3 SQL conventions

- UUIDv7 values are generated by trusted application code so indexes have time locality. Random UUIDv4 remains valid for externally supplied correlation ids.
- Every tenant-owned primary/unique key includes tenant_id. Every repository method receives tenant_id explicitly.
- Times are UTC timestamptz. Business time belongs in typed payload schemas; recorded_at is not a substitute.
- Money/cost is integer microunits plus currency/price-book version. Token and byte counters are bigint.
- SHA-256 values are 32-byte bytea, not ambiguous hex strings.
- Enum changes use additive migrations; externally visible event/error codes use constrained text catalogs when independent deployment is required.
- JSONB holds bounded schema-validated structures. Searchable/high-cardinality identifiers are columns. Large bodies are artifacts.
- Mutable “current” rows are projections over immutable attempts/events/deltas where practical. Terminal attempt/event/audit rows are append-only.
- All update/delete operations carry tenant_id and, for leased runtime writes, the expected fencing_token.

The DDL below is the logical production schema. High-volume table partitioning is generated per cell as described in Section 14.19; migration tooling, not handwritten one-off DDL, creates future partitions.

~~~

`environment` is the current placement pointer; `environment_placement` is its immutable routing-epoch history. A placement change is one fenced transaction that retires or drains the old row, inserts the next epoch, and switches the current pointer. Existing executions keep their pinned historical placement while new admissions use the current row. `control_endpoint` is a workload-identity URI, not a secret-bearing network URL.

storage_locator is an opaque internal object key, never a presigned URL. Secret-bearing URLs are generated only at access time.

    (replay_operation = 'NONE'
      AND replay_source_execution_id IS NULL
      AND replay_source_through_sequence IS NULL
      AND replay_source_event_id IS NULL
      AND replay_source_history_hash IS NULL
      AND replay_fork_sequence IS NULL
      AND replay_approval_id IS NULL
      AND (
        (execution_mode = 'LIVE'
          AND adapter_effect_mode = 'REEXECUTE_AUTHORIZED_EFFECT')
        OR
        (execution_mode = 'SIMULATION'
          AND adapter_effect_mode IN ('FORBID', 'REEXECUTE_READ_ONLY'))
      ))
    OR
    (replay_operation = 'STATE_REBUILD'
      AND replay_source_execution_id IS NOT NULL
      AND replay_source_through_sequence IS NOT NULL
      AND replay_source_event_id IS NOT NULL
      AND replay_source_history_hash IS NOT NULL
      AND replay_fork_sequence IS NULL
      AND replay_approval_id IS NULL
      AND execution_mode = 'REPLAY'
      AND adapter_effect_mode = 'FORBID')
    OR
    (replay_operation = 'EXACT_REPLAY'
      AND replay_source_execution_id IS NOT NULL
      AND replay_source_through_sequence IS NOT NULL
      AND replay_source_event_id IS NOT NULL
      AND replay_source_history_hash IS NOT NULL
      AND replay_fork_sequence IS NULL
      AND replay_approval_id IS NULL
      AND (
        (execution_mode = 'REPLAY'
          AND adapter_effect_mode = 'SUBSTITUTE_RECORDED')
        OR
        (execution_mode = 'SIMULATION'
          AND adapter_effect_mode = 'REEXECUTE_READ_ONLY')
      ))
    OR
    (replay_operation = 'FORKED_REPLAY'
      AND replay_source_execution_id IS NOT NULL
      AND replay_source_through_sequence IS NOT NULL
      AND replay_source_event_id IS NOT NULL
      AND replay_source_history_hash IS NOT NULL
      AND replay_fork_sequence = replay_source_through_sequence
      AND (
        (execution_mode = 'REPLAY'
          AND adapter_effect_mode = 'SUBSTITUTE_RECORDED'
          AND replay_approval_id IS NULL)
        OR
        (execution_mode = 'SIMULATION'
          AND adapter_effect_mode IN ('FORBID', 'REEXECUTE_READ_ONLY')
          AND replay_approval_id IS NULL)
        OR
        (execution_mode = 'LIVE'
          AND adapter_effect_mode = 'FORBID'
          AND replay_approval_id IS NULL)
        OR
        (execution_mode = 'LIVE'
          AND adapter_effect_mode = 'REEXECUTE_AUTHORIZED_EFFECT'
          AND replay_approval_id IS NOT NULL)
      ))
  )
);

Admission uses a separate idempotency record to guarantee uniqueness and store the original response. A deferred invariant trigger verifies that `execution`, `execution_pin`, the selected `deployment_target`, `graph_compilation`, and `compiled_plan` agree on GraphVersion, compilation, semantic plan hash, signed envelope hash, deployment revision, policy snapshot, traffic selection, and home-cell routing epoch. For `SUBGRAPH`, the same trigger locks the parent execution/activation and requires the child to inherit `root_execution_id`, home cell, routing epoch, and a budget reservation bounded by the parent's remaining budget; non-subgraph origins are roots by constraint. A publish/admission transaction also requires the PolicySnapshot to belong to the selected environment, remain unexpired, and have no revoked member. These values never follow later deployment or policy pointers.

The three replay axes are persisted independently: `replay_operation` states the reconstruction action, `execution_mode` governs time/nondeterminism semantics, and `adapter_effect_mode` governs external effects. `STATE_REBUILD` is `REPLAY/FORBID`. `EXACT_REPLAY` is either `REPLAY/SUBSTITUTE_RECORDED` or an isolated `SIMULATION/REEXECUTE_READ_ONLY` comparison. `FORKED_REPLAY` additionally pins the source history boundary; it may continue in replay, simulation, or explicitly authorized live mode. A live fork that reexecutes authorized effects must bind a fresh PolicySnapshot and content-bound approval. The admission transaction validates the source event/sequence/history hash, stores the lineage before work exists, and rejects an invalid combination without creating an execution row.

The completion update always joins execution_token and compares fencing_token. A unique attempt ordinal prevents duplicate attempts from being recorded as the same attempt; it does not substitute for fencing. Scope close locks the canonical `execution_scope`, verifies the caller is its compiled owner and all child obligations are terminal, and commits the close plus StateWriteIntent and dependent readiness in one transaction. The ordinary unique constraint permits many unaccepted signals with a null `accepted_sequence`, while preventing two accepted signals from owning the same non-null execution-local sequence. A supplied `expected_wait_id` must name the current tenant/execution/signal wait and generation; a stale or already terminal wait returns conflict instead of matching a later wait with the same name. Inbox-style signals without an expected wait remain durable but may be consumed only by an explicit compiled correlation policy. Matching locks and terminalizes the wait, binds `matched_signal_id`, assigns the execution event sequence, and makes dependents ready in one transaction.

An effect id is derived from stable logical identity—tenant, execution, activation, compiled effect name, and effect ordinal—and deliberately excludes request bytes. Every ledger row also has a platform-only `operation_key_hash = digest("effect-operation-key", effect_id)` for internal reservation and receipt correlation. For `NATIVE` or `ADAPTER` idempotency, the compiler-owned expression yields a separate `destination_idempotency_key_hash`; its partial unique index serializes destination-scoped reservation, and a retry under that key must present the same `canonical_request_hash`. For `NONE`, the destination hash is NULL and no destination idempotency header/key is claimed or sent. `IDEMPOTENT_WRITE` is effectively-once only when the destination or transactional adapter enforces its binding. Other write classes may finish `UNKNOWN` and stop for reconciliation rather than claiming exactly once. Replay persists its adapter mode per operation; recorded substitution references the immutable source effect and never invokes the adapter.

      AND conflict_policy = 'FAIL_CONFLICT')
    OR
    (operation IN ('PUT', 'BIND_ARTIFACT')
      AND path_mutability = 'SINGLE_ASSIGNMENT'
      AND conflict_policy = 'FAIL_CONFLICT')
    OR
    (operation IN ('PUT', 'DELETE', 'BIND_ARTIFACT')
      AND path_mutability = 'COMPARE_AND_SET'
      AND conflict_policy IN
        ('FAIL_CONFLICT', 'RECOMPUTE', 'SERIALIZE_SCOPE'))
    OR
    (operation = 'REDUCE'
      AND path_mutability = 'REDUCER'
      AND conflict_policy = 'APPLY_REDUCER')
  )
);

CREATE INDEX state_intent_conflict_idx
  ON ege.state_delta_intent
    (tenant_id, top_level_fragment, normalized_path, state_delta_id);

CREATE TABLE ege.state_fragment_head (
  tenant_id             uuid NOT NULL,
  execution_id          uuid NOT NULL,
  top_level_fragment    text NOT NULL,
  version               bigint NOT NULL CHECK (version >= 0),
  value_hash            ege.sha256 NOT NULL,
  value_artifact_id     uuid,
  inline_value          jsonb,
  PRIMARY KEY (tenant_id, execution_id, top_level_fragment),
  FOREIGN KEY (tenant_id, execution_id, version)
    REFERENCES ege.state_version(tenant_id, execution_id, version),
  FOREIGN KEY (tenant_id, value_artifact_id)
    REFERENCES ege.artifact(tenant_id, id),
  CHECK ((value_artifact_id IS NULL) <> (inline_value IS NULL))
);
~~~

The wire protocol carries only operation, path, optional expected path version/value hash, dedupe key, and value. WorkerGateway looks up `path_mutability`, `conflict_policy`, and `reducer_digest` from the pinned CompiledPlan; a worker cannot select them. The committed intent stores that resolved policy so replay needs no mutable lookup. One completion carries at most 1,024 intents. The completion transaction requires the wire count to equal `state_delta.intent_count`, inserts contiguous ordinals `0..intent_count-1`, and rejects a missing, duplicate, or extra row. It locks `state_document` plus affected `state_fragment_head` rows in sorted fragment order, queries intervening intents for overlapping normalized JSON Pointer paths, and applies the pinned policy. PostgreSQL cannot express path-prefix overlap as a simple foreign key; the repository layer owns that deterministic validation and is covered by concurrency tests.

Normative lowering is lossless and versioned:

| Compiled path policy | Allowed wire intent | Stored operation | Commit rule |
|---|---|---|---|
| `IMMUTABLE` | compiler/initializer `PUT` only | `PUT` | path must be absent and writer must be `$initializer`; runtime node writes reject |
| `SINGLE_ASSIGNMENT` | `PUT` or `BIND_ARTIFACT` | same | path must be absent; identical duplicate by intent dedupe key is idempotent |
| `COMPARE_AND_SET` | `PUT`, `DELETE`, or `BIND_ARTIFACT` | same | `expected_path_version` is required and must match; optional value hash adds compare protection |
| `REDUCER` | `REDUCE` | `REDUCE` | gateway supplies the pinned reducer digest; delta is applied in canonical plan order |
| scope owner | `CLOSE_SCOPE` | `CLOSE_SCOPE` | no value; scope must be open and all declared child obligations terminal |

`FAIL_CONFLICT`, `RECOMPUTE`, `APPLY_REDUCER`, and `SERIALIZE_SCOPE` are CompiledPlan conflict actions. They are never trusted from a worker result. A schema/permission violation fails the attempt; a genuine MVCC conflict follows the pinned action.

## 14.17 Audit schema

Audit events answer who requested, authorized, changed, executed, approved, accessed, exported, or redrove what, under which policy and version. They are not application debug logs.

The audit writer locks audit_stream, assigns sequence, calculates:

~~~text
event_hash = SHA-256(

~~~

and updates head_hash in the same transaction. Hash chaining detects alteration but does not prevent a privileged database attacker from replacing an entire chain; signed periodic exports to separately administered immutable storage provide external anchoring.

## 14.19 Physical partitioning and index plan

The logical DDL is materialized differently for high-volume tables:

| Table | Partition key | Local index / retention |
|---|---|---|
| execution | hash tenant virtual bucket, optionally subpartition by admitted month | active partial index; terminal month archive |
| activation/token/attempt/dependency | same tenant/execution bucket as execution | status/lease/activation indexes |
| execution_event | hash tenant/execution bucket, time-tiered export | execution sequence and event-type/time |
| state_version/delta/intent | hash tenant/execution bucket | execution/version and fragment/path |
| outbox | hash cell partition plus available-time scan | partial PENDING/PUBLISHING |
| log chunk | tenant bucket plus min_timestamp month | execution/sequence lookup |
| audit event | tenant/audit-stream bucket plus recorded month | stream sequence, actor/resource lookup |
| metric rollup | bucket_start month | tenant/execution/metric |

Production migration generation follows this pattern conceptually:

~~~sql
-- Parent definition shown as a physicalization example.
CREATE TABLE ege.execution_event_p (
  LIKE ege.execution_event INCLUDING DEFAULTS INCLUDING CONSTRAINTS
) PARTITION BY HASH (tenant_id, execution_id);

-- Migration generator creates 64 or 256 buckets based on measured size.
CREATE TABLE ege.execution_event_p_000
  PARTITION OF ege.execution_event_p
  FOR VALUES WITH (MODULUS 64, REMAINDER 0);

CREATE UNIQUE INDEX execution_event_p_000_sequence_uq
  ON ege.execution_event_p_000 (tenant_id, execution_id, sequence);
CREATE UNIQUE INDEX execution_event_p_000_event_id_uq
  ON ege.execution_event_p_000 (tenant_id, event_id);
~~~

The exact bucket count is a migration-time constant. It is not changed casually: repartitioning is an online copy/verify/cutover operation. Cell-level database sharding precedes extreme per-table partition counts.

For time-based archival, the platform either subpartitions leaf buckets by recorded month with partition-compatible keys, or copies terminal ranges into verified archive tables/object bundles before bounded deletion. Cross-partition global uniqueness is maintained by the execution sequence allocator and idempotency tables; tests validate it during archiving.

Indexes are justified by named queries. No general GIN index is placed over unbounded log/event JSONB. Projection stores serve exploratory analytics.

## 14.20 Tenant isolation and database roles

Every request transaction sets trusted session context after authentication:

~~~sql
BEGIN;
SET LOCAL ege.tenant_id = '019fd4b4-2031-7e4b-914c-83d9b2ebd146';
SET LOCAL ege.principal_id = 'principal:019fd4...';
SET LOCAL statement_timeout = '5s';
SET LOCAL lock_timeout = '500ms';
-- repository query with explicit tenant_id predicate
COMMIT;
~~~

Representative row-level policy:

~~~sql
ALTER TABLE ege.graph ENABLE ROW LEVEL SECURITY;
ALTER TABLE ege.graph FORCE ROW LEVEL SECURITY;

CREATE POLICY graph_tenant_isolation ON ege.graph
  USING (
    tenant_id = nullif(current_setting('ege.tenant_id', true), '')::uuid
  )
  WITH CHECK (
    tenant_id = nullif(current_setting('ege.tenant_id', true), '')::uuid
  );
~~~

Equivalent generated policies apply to every tenant-owned table. RLS is defense in depth; repository queries still require `tenant_id`. Table owners are not used by application services. Separate roles exist for control API, scheduler/coordinator, WorkerGateway, outbox, projector, audit writer, archive, and migration. WorkerSupervisors and sandbox runners have no PostgreSQL role or network route; they claim, heartbeat, and submit results only through authenticated WorkerGateway RPCs. The gateway role can execute narrowly scoped claim/heartbeat/completion repository functions but cannot mutate graph versions or audit history. Projectors cannot update canonical runtime state.

Append-only history tables deny UPDATE/DELETE to runtime roles. GDPR/privacy deletion is an explicit privileged lifecycle workflow using legal-hold checks, tombstones, artifact key destruction where lawful, and an audit record; it is not an ordinary row delete.

## 14.21 Transaction boundaries

### 14.21.1 Admission

One SERIALIZABLE or carefully constrained READ COMMITTED transaction:

1. insert/lock idempotency_record;
2. resolve and validate deployment revision, selected deployment target, GraphVersion, CompiledPlan, and PolicySnapshot;
3. insert execution and execution_pin;
4. create state_document/version zero and execution_budget;
5. persist input artifact reference;
6. append ExecutionAdmitted event and audit record;
7. insert wakeup and outbox message;
8. mark idempotency record COMPLETED with response reference.

Same idempotency key with a different request_hash returns a conflict.
Schema, identity, authorization, policy, quota, capacity, and infeasible-deadline failures terminate the admission decision and idempotency response without creating an `execution` row. `ADMITTED` is therefore the first execution status; rejection is not a fictitious terminal run.

### 14.21.2 Claim

WorkerGateway authenticates the WorkerSupervisor and executes one short transaction. It locks the execution/token, then requires:

- the supplied outbox message exists and its payload binds this `execution_token_id` plus `readiness_generation`;
- token status is `READY` or eligible `RETRY_WAIT`, `available_at <= database_now()`, and the readiness generation matches;
- execution environment, home cell, and `routing_epoch` match the gateway cell;
- execution `scheduler_fence`, token `scheduler_fence`, and requested scheduler fence match;
- the worker build, node contract, pool, and attested capability class belong to the CompiledPlan's `worker_compatibility_set`;
- the execution is non-terminal, non-cancelling, within deadline/budget, and its pinned `plan_hash` matches the token.

It compare-and-sets the token to `RUNNING`, increments `fencing_token` and `attempt_ordinal`, copies routing/scheduler/plan fences into a new `node_attempt`, derives canonical attempt-scoped ExecutionGrant claims, stores their hash, consumes a concurrency permit, and appends `AttemptClaimed`. After commit, WorkerGateway signs that proof-of-possession grant for the authenticated WorkerSupervisor. The supervisor may present it only to WorkerGateway; the sandbox never receives it, and it grants no direct database, broker, secret, or adapter access. Queue acknowledgement follows successful claim or an authoritative already-terminal/stale response; a transient gateway/database failure leaves the hint unacknowledged.

### 14.21.3 Completion

One transaction:

1. authenticate the WorkerSupervisor, verify the mTLS-bound ExecutionGrant against `node_attempt.execution_grant_hash`, and lock execution, token, and attempt;
2. require token `RUNNING`, lease owner identity, attempt id/ordinal, routing epoch, scheduler fence, fencing token, and plan hash to match the request and pinned rows;
3. require `lease_expires_at > database_now()`—there is no completion grace period;
4. validate result artifacts are `COMMITTED` and hashes match; lock and load the complete canonical `effect_operation` set for `(tenant_id, execution_id, activation_id)`; reject any supplied receipt that is absent from or disagrees with that set on effect id, the outcome projection below, deterministic operation-key hash, destination-idempotency-key hash, or canonical request hash;
5. normalize every transient effect under the same locks. A trusted `OUTCOME_NOT_STARTED` means adapter processing reserved the effect but proved the external destination operation was never invoked, and changes matching `RESERVED` to `NOT_COMMITTED`; `OUTCOME_NOT_COMMITTED` changes `STARTED` to `NOT_COMMITTED` only with trusted adapter proof. `COMMITTED`, `REJECTED`, `UNKNOWN`, and `RECONCILING` map one-to-one. No receipt ever exposes `RESERVED` or `STARTED`; an unresolved `STARTED` becomes `UNKNOWN`, not `NOT_COMMITTED`;
6. derive success, retry, stop, or reconciliation from the complete normalized effect set—not the request list. Success is forbidden unless every row is in the terminal set `{COMMITTED, NOT_COMMITTED, REJECTED}` and the pinned node policy permits that handled outcome. Any remaining `RESERVED` or `STARTED` rejects terminalization. Retry is forbidden for an ambiguous, already committed, or destination-rejected effect unless the pinned adapter policy explicitly resolves it to a safe disposition. The repeated request receipts are consistency evidence only, so an empty or partial list never asserts that no effects exist;
7. if any effect is `UNKNOWN` or `RECONCILING`, execute the ambiguity branch: reject the worker output and StateWriteIntents; settle only trusted metering/budget facts; terminalize the Attempt as `UNKNOWN_EFFECT`, mark the ExecutionToken `TERMINAL`, and park the Activation in nonterminal `UNKNOWN_EFFECT` with `terminal_at = NULL`; append ambiguity/audit events and a reconciliation wakeup/outbox record; commit and return. Do not mutate materialized state, append `NodeCompleted`, or make ordinary success dependents ready. Authorized reconciliation later moves the Activation to `SUCCEEDED`, `RETRY_WAIT`, or `FAILED`; the retry transition mints a new ExecutionToken;
8. only on the non-ambiguous branch, reconcile the budget reservation and append the ledger/usage receipt;
9. validate each StateWriteIntent against CompiledPlan path policy, lower it to canonical stored operations, and commit the MVCC state version;
10. terminalize attempt, activation, and token for the derived success/failure disposition;
11. append execution events;
12. update dependency rows/counters or `execution_wakeup`;
13. insert outbox notifications with a new outbox id/readiness generation for every new ready transition.

No network or object upload occurs while locks are held.

### 14.21.4 Outbox relay

Relay claims `PENDING` messages with `SKIP LOCKED` and its own fence, publishes with `Nats-Msg-Id = outbox_message.id`, then marks `PUBLISHED` if the fence matches. A dispatch subject is `dispatch.<cell>.<pool>.<priority_band>.<shard>`. Its non-authoritative payload contains `outbox_id`, `tenant_id`, `environment_id`, `home_cell_id`, `routing_epoch`, `scheduler_fence`, `execution_token_id`, `readiness_generation`, `plan_hash`, and a non-secret trace link—never authority, inputs, or credentials. WorkerGateway authenticates the supervisor and verifies every payload field against canonical rows; the tenant key is mandatory because token identity is tenant-composite. Every newly committed ready/retry transition increments readiness generation and creates a new outbox id; relay retries of that transition reuse the same outbox id. Crash after publish before mark causes duplicate delivery, which consumers deduplicate before WorkerGateway claims canonical work.

## 14.22 Retention, archive, and deletion

Retention is independently configured for:

- graph sources/revisions and signed packages;
- execution summaries/history;
- state deltas/checkpoints;
- model/tool inputs and outputs;
- diagnostic logs;
- metrics projections;
- audit and security records;
- idempotency keys and dead letters.

Archive workflow:

~~~text
select closed immutable range
-> export canonical rows and referenced artifacts
-> create sorted manifest with row counts, min/max keys, schemas, hashes
-> sign and replicate manifest/bundles
-> restore into isolated verifier and sample replay
-> commit archive catalog entry
-> wait policy grace period
-> detach/delete hot partitions
~~~

References from active executions, checkpoints, replay forks, DLQ entries, audit/legal hold, or unresolved effects block deletion. Object garbage collection calculates reachability from canonical manifests and waits a safety interval.

## 14.23 Data invariants not delegated to projections

The application and database jointly enforce:

1. one immutable graph revision and dependency lock per execution;
2. one current token per activation;
3. one current fencing token and no stale completion;
4. consecutive attempt ordinals per activation;
5. exactly one terminalization of attempt/activation/execution;
6. execution-local strictly increasing event sequence;
7. state version increments by one with a matching delta;
8. no shared-state lost update outside an explicit conflict policy;
9. one request body per idempotency key;
10. one effect request hash per effect id;
11. budget consumption plus reservations never exceeds hard admitted limits;
12. outbox intent commits with the state it announces;
13. a VALID checkpoint references durable verified objects;
14. audit chain sequence/hash continuity;
15. no current authorization or version decision comes from a rebuildable projection.

Invariant-check jobs read replicas when safe, but repairs occur on the primary through audited, fenced workflows. A mismatch quarantines affected execution/partition; it is never silently “fixed” from ClickHouse or Redis.

## 14.24 Migration and compatibility policy

Database schema migrations use expand/backfill/verify/switch/contract. Event, Graph IR, state, checkpoint, log, metric, and audit schemas have independent integer versions. Field-number or enum reuse is prohibited. Consumers accept current and previous supported versions and use deterministic, tested upcasters for historical replay.

Published graph/schema/package/plugin bytes remain readable for at least their execution/audit retention. Revocation blocks new use but does not erase evidence required to explain past runs.

A migration release is accepted only after:

- DDL lock and rewrite behavior is measured on production-sized copies;
- old and new binaries run concurrently;
- backfills are resumable and idempotent;
- per-partition row counts/hashes and foreign-key or equivalent checks pass;
- replay of sampled executions matches before/after;
- rollback boundaries and irreversible steps are documented;
- backup restore succeeds at the new schema version.

## 14.25 Design decisions and trade-offs

| Decision | Why | Alternative | Trade-off / failure mode |
|---|---|---|---|
| PostgreSQL canonical relational model | Atomic state/outbox/budget/audit transitions and enforceable tenancy | Queue/event store or graph DB as primary | Write/shard engineering; strong recovery semantics |
| Immutable bodies in object storage | Scales payloads and enables content verification | Large JSONB/queue payloads | Artifact lifecycle/integrity must be operated |
| Typed columns plus bounded JSONB | Stable indexes with extensible manifests | EAV or all-JSON tables | Schema migrations remain necessary |
| Composite tenant keys | Prevents accidental cross-tenant FK/reference | Global ids alone | Wider indexes; explicit isolation |
| Activation id as deterministic digest | Idempotent expansion/replay identity | Random id for every materialization | Debug display needs encoded form |
| Separate attempt and effect records | Worker retry differs from destination outcome | Store only node status | More rows; ambiguous effects become tractable |
| MVCC delta plus fragment heads | Parallel compute and audited conflicts | Mutable state blob | More commit logic/storage; no lost updates |
| Append-only event/audit with current rows | Explanation and replay plus fast queries | Event-only or snapshot-only | Dual representation needs invariant checks |
| Bounded audit hash streams | Tamper evidence without tenant-global lock | One global chain | Several signed chain heads, simpler scale |
| Projections explicitly rebuildable | Prevent split authority | ClickHouse/Redis/search as current state | Projection lag/rebuild tooling is visible |

## 14.26 Failure modes and operational response

| Failure | Detection | Response |
|---|---|---|
| Duplicate admission | idempotency PK | return stored response if hash matches; conflict otherwise |
| Stale worker completion | fence predicate updates zero rows | mark attempt lease-lost; discard/quarantine late result |
| State delta/version mismatch | constraints/invariant checker | rollback commit; quarantine on persisted corruption |
| Budget ledger/current mismatch | fold ledger versus aggregate | block new reservations; audited rebuild aggregate |
| Outbox row publishes twice | message id/consumer claim | idempotent consume; record redelivery metric |
| Orphan object | object inventory absent from artifact/reference graph | delete after grace and two-pass verification |
| Missing object for artifact | manifest verifier/read failure | quarantine artifact and dependent execution/checkpoint |
| Audit chain break | sequence/hash verifier | security incident; compare signed export anchor |
| Projection corruption | offset/checksum/reconciliation | discard generation and rebuild |
| Partition missing/future horizon | preflight/insert failure alarm | stop affected admission; create verified partition |
| Schema upcaster missing | replay validation | fail closed; restore supported binary/upcaster |
| Cross-tenant reference attempt | composite FK/RLS/repository guard | reject and emit security audit event |

## 14.27 Schema acceptance tests

The data layer is production-ready only when automated tests prove:

1. every tenant-owned FK rejects a different tenant id;
2. RLS denies reads/writes with missing or mismatched tenant context;
3. published revisions/artifact hashes cannot be mutated by runtime roles;
4. duplicate admission, signal, outbox delivery, state append, and effect completion are idempotent;
5. stale fencing tokens cannot heartbeat, write state, charge budget, or complete;
6. concurrent budget reservations cannot oversubscribe any dimension;
7. concurrent state commits obey the pinned `IMMUTABLE`/`SINGLE_ASSIGNMENT`/`COMPARE_AND_SET`/`REDUCER` mutability and `FAIL_CONFLICT`/`RECOMPUTE`/`APPLY_REDUCER`/`SERIALIZE_SCOPE` actions for the five canonical stored operations;
8. event sequence and audit chain remain continuous through crashes;
9. VALID checkpoint constraints and verifier reject missing/corrupt artifacts;
10. archive/export/restore retains row counts, hashes, schemas, lineage, and replay;
11. deleting Redis, JetStream retained messages, ClickHouse, and search indexes changes no canonical answer;
12. production-scale partitions sustain claim/completion queries without unbounded scans;
13. migration rollback and mixed-version operation preserve event/state compatibility;
14. legal hold blocks archive deletion and artifact garbage collection.
